# AI providers

Pulse calls AI models through the [Laravel AI SDK](https://laravel.com/docs/13.x/ai-sdk) (`laravel/ai`). It is not tied to one provider: any provider defined in `config/ai.php` (Anthropic, Gemini, OpenAI, Mistral, Groq, DeepSeek, OpenRouter, xAI, Ollama, OpenAI-compatible endpoints, Z.AI as `zai` through its OpenAI-compatible API, …) can be used in the instance chain. Accounts can also supply their own provider keys.

Both digest pipelines call `AiChainResolver::for($user)`. Personal keys take precedence; the instance chain is available only to accounts granted `uses_instance_ai`.

## Choosing providers

For accounts with instance AI access and no personal keys, `DIGEST_AI_PROVIDERS` is an ordered list of `provider:model` pairs:

```dotenv
DIGEST_AI_PROVIDERS="gemini:<model>,anthropic:claude-haiku-5-5"
GEMINI_API_KEY=...
ANTHROPIC_API_KEY=...
```

The first provider is tried first. The SDK fails over to the next one when a provider is rate limited, overloaded, out of credits or unreachable (a connection error or timeout). News falls back to saved headlines without summaries when the SDK exhausts failover providers or returns no structured output. Other errors (an invalid request, for example) fail news generation. Missing AI configuration also fails generation when candidates need AI. A quiet news post skips AI. Learning has no fallback text and fails generation for a later retry.

The provider names are the keys of `config/ai.php`; each provider reads its own API key there (`GEMINI_API_KEY`, `ANTHROPIC_API_KEY`, …). A model must always be given, so a provider upgrade never silently changes the model.

## Per-user keys

`ai_keys` stores one key per user and provider. Supported providers are `gemini`, `anthropic`, `openai`, `groq` and `openrouter`. Each row holds the model, encrypted `api_key` (hidden from serialization), `key_suffix` (the last four characters), failover `position` and `consented_at`.

`AiChainResolver::for($user)` resolves the SDK provider chain:

1. With user keys, build providers using those keys in ascending `position` order.
2. Without user keys, use `ProviderChain::fromConfig()` (`DIGEST_AI_PROVIDERS`) only if `uses_instance_ai` is true.
3. Otherwise, throw `AiNotConfiguredException`.

The user's chain never falls back to instance keys. `uses_instance_ai` is hidden and excluded from mass assignment; `pulse:adopt` grants it through Artisan.

## Agents

Each AI task is an agent class in `app/Ai/Agents/` that implements the SDK's `Agent` and `HasStructuredOutput` contracts: it has instructions and a JSON schema, so the answer always has the same shape whichever provider produced it.

| Agent | Used by | Returns |
|---|---|---|
| `HealthCheck` | `digest:ai` | `{ok}` |
| `NewsCurator` | the news selection | `{items: [{candidate_id, url, title, summary, tags}]}` |
| `LearningWriter` | the tip + topic of the day | `{tip: {title, body, tags}, topic: {body, stack_angle, links: [{title, url}], tags}}` |

`NewsCurator`'s instructions include the user's profile (left out when empty), interest names, maximum number of items and existing tags, so the model reuses them instead of creating near-duplicates ("ai" vs "artificial-intelligence"). The candidates are sent as JSON in the prompt. `LearningWriter` receives the user's profile and their last 60 tip titles; its optional `stack_angle` becomes an "In practice:" paragraph applying the topic to the reader's stack.

## Health check

```bash
docker compose exec app php artisan digest:ai
```

It checks the instance chain from `DIGEST_AI_PROVIDERS`, not per-user keys. It sends one tiny structured prompt to **each** provider separately (through the chain, a broken first provider would be hidden by the failover) and prints which ones work. It exits with an error code if any provider fails or the configuration is invalid.

## Tests

Agents are faked with the SDK's testing helpers, so the test suite never calls a real provider:

```php
HealthCheck::fake([['ok' => true]])->preventStrayPrompts();
HealthCheck::assertPromptedTimes(1);
```

With `laravel/ai` 1.2, a fake callback receives `(string $prompt, $attachments, $provider, string $model)`, not the `AgentPrompt` object shown in the SDK docs; `assertPrompted()` callbacks do receive an `AgentPrompt`.
